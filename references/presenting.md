# 放映、双屏演讲者视图与导出

## 打开与浏览

双击 HTML 文件用浏览器打开（推荐 Chrome/Edge；Safari/Firefox 可放映但无自动双屏，见下文降级）。
底部居中一条统一中文控制条（鼠标动时出现）；浏览态与放映态自动切换按钮组：

```
浏览态：[◀] [ 3 / 71 ] [▶] │ [回首页 R] │ [放映 F] [演讲者放映 P] │ [?]
放映态：[◀] [ 3 / 71 ] [▶] │ [黑屏 B] │ [全屏/窗口 F] [退出放映 Esc] │ [?]
```

- 页码可单击 → 输入页码回车跳转；也可直接敲数字键缓冲跳页（如 `3`、`7`、`Enter` 跳第 37 页，单个数字停 0.8 秒自动跳）。
- 左侧缩略图栏：点击跳页、拖拽排序、右键 Skip/Move/Duplicate/Delete（**注意**：这些结构操作只改当前浏览器会话，不落盘；正式增删页要改 HTML 源文件）。

| 键 | 功能 | 提供方 |
|---|---|---|
| → ↓ 空格 Enter PgDn / ← ↑ Backspace PgUp | 下一页 / 上一页 | deck-stage + presenter 层 |
| 滚轮 | 翻页（阈值 + 450ms 冷却防触控板连翻） | presenter 层 |
| 数字 + Enter | 跳到任意页（缓冲式，兼容旧 1–9/0 直跳） | presenter 层 |
| Home / End / R | 首页 / 末页 / 回首页 | deck-stage |
| `F` | 浏览时：从当前页全屏放映；放映中：全屏⇄窗口放映切换；`Shift+F` 从第 1 页放映 | presenter 层 |
| `P` | 演讲者放映（双屏自动投片；单屏弹选择卡，可选窗口放映——远程会议用） | presenter 层 |
| `X` | 交换两个屏幕的内容（仅双屏放映中） | presenter 层 |
| `B` | 黑屏 / 恢复（任意翻页键也恢复；双窗状态同步） | presenter 层 |
| `Esc` | 退出放映（双屏放映的全屏中：第一次退全屏落窗口放映，再按一次退出） | presenter 层 |
| `H` / `?` | 快捷键帮助与关于（含作者与开源仓链接、“导出 PDF”按钮） | presenter 层 |

**F5 为浏览器刷新**（刷新后页码经 URL hash 自动恢复，是意外情况下的恢复路径），放映请用 `F` / `P`。

## 手机与平板

讲完之后 deck 常会作为链接流转，绝大多数打开发生在手机上，所以触屏是一等形态，不是降级形态。
判据用指针粗细 `(pointer: coarse) && !(pointer: fine)`，不用屏幕宽度，桌面窗口拖窄不受影响。

**竖屏＝阅读态。** 幻灯片贴屏幕顶部按屏宽铺满（16:9 在 9:19 的屏上只占约三成高），
下面七成交给本页逐字稿，正文 16 点可独立滚动。这不是附加功能：上屏只放锚点的 deck
脱离讲者本就不自足，补的正是这一半。本页没有逐字稿时不建面板，幻灯片回到垂直居中。

**横屏＝观看态。** 幻灯片按屏幕铺满，不显示逐字稿面板。iPhone 横屏实测占屏 82%。

| 手势 / 控件 | 作用 |
|---|---|
| 左右滑动 | 上一页 / 下一页（位移 ≥ 48 点且横向大于纵向 1.5 倍才判定） |
| 点左右半屏 | 上一页 / 下一页 |
| 逐字稿面板内纵向滑 | 滚动正文，不翻页 |
| 画布下沿细线 | 当前进度 |
| 控制条田字格按钮 | 缩略图总览，两列起步，点格跳页 |

触屏上控制条常驻不淡出，并且只保留上一页、页码、下一页、总览、帮助；
放映、演讲者放映、黑屏、全屏这些上台按钮全部移除，缩略图栏也一律不外露。

**不提供全屏按钮，也不提供锁横屏。** MDN 兼容数据（2026-08-13 拉取）：
`Element.requestFullscreen` 在 iPhone Safari 上没有实现（仅 iPad 有），
`ScreenOrientation.lock` 在 Safari 全系不支持。凡是要向平台申请才生效的能力，
都不能放在主路径上；手机端的横屏只能是布局，不能是按钮。

## 放映（对标 PowerPoint）

放映有两种**表面**：**全屏放映**（OS 全屏）与**窗口放映**（不进全屏，窗口内干净画布——
缩略图栏与全部浏览 UI 隐藏、画布满窗、四周黑边）。两者随时用 `F` 或控制条按钮互切，
放映不中断。术语分工（全文统一）：

| 术语 | 指代 |
|---|---|
| 全屏放映 / 窗口放映 | 放映的两种表面状态（`F` 互切） |
| 演讲者放映 | `P` 触发的整套双窗行为 |
| 演讲者视图 | 讲者看的那扇窗（标题带“（演讲者视图）”） |
| 放映窗口 | 观众看的那扇窗（放映中标题带“（放映窗口）”） |

**“放映”（`F`）= 从当前页全屏**，适用单屏或“镜像”投屏（观众与你看到相同画面）。
放映态鼠标移动浮现精简控制条（翻页/黑屏/全屏⇄窗口/退出放映），光标静止 2 秒自动隐藏；
末页再前进出黑色结束屏（“放映结束，再按一次退出放映”），收场不慌。

**“演讲者放映”（`P`）= 一键双屏**（Chrome/Edge，系统显示设置为“扩展”模式）：

1. 点“演讲者放映”或按 `P`——首次会弹“管理窗口”授权（**允许**，浏览器会记住）；
2. 幻灯片自动全屏到**外接屏/投屏**，演讲者视图自动落在**本机屏幕**：
   当前页大图 + 下一页预览 + 逐字稿（`A−/A＋` 调字号并记忆）+ 计时器/时钟 +
   跳页 + 所有页面缩略图网格 + 黑屏 + 放映窗口状态（已连接 · 全屏/窗口放映）；
3. 任意一侧翻页另一侧自动跟随（postMessage 同步，file:// 下可用）；
4. **投反了**？演讲者视图头部点“交换屏幕”（或任一窗口按 `X`），两屏内容一键对调；
5. 结束：演讲者视图点“结束放映”——投屏退出放映、报告总用时、演讲者窗自关。

**“退出放映”vs“结束放映”**：放映窗口的“退出放映”（Esc）只退出放映态，演讲者视图
保留并出“放映已结束＋重新放映”横幅（可一键反悔续场）；演讲者视图的“结束放映”是
正式收场——报总用时并自关窗口。

## 远程会议：共享放映窗口（一等场景）

单屏入会（腾讯会议、Zoom、飞书会议等）在会议软件中共享放映窗口，观众只看到干净画面、
讲稿留在本机：

1. **先把 deck 所在标签拖出成独立浏览器窗口**（关键：窗口共享会把整个浏览器窗口连
   标签栏、地址栏一起共享出去；讲中途查资料一律用另一个浏览器窗口，别在共享窗里开新标签）；
2. 按 `P` → 选择卡点“演讲者视图＋窗口放映”——演讲者视图弹出，本窗口自动进入窗口放映；
3. 在会议软件的共享选择器里选**标题带“（放映窗口）”的窗口**（带“（演讲者视图）”的是
   讲稿，千万别选反）；
4. 讲者窗盖在放映窗上**不影响共享画面**——现代窗口级捕捉取的是窗口内容而非屏幕像素，
   观众看不到遮挡；
5. 远程共享保持窗口放映即可，无需全屏；翻页在演讲者视图操作，两窗自动同步；
6. 结束顺序：**先在会议软件停止共享，再点“结束放映”**（否则观众会看到放映结束
   toast 与浏览态缩略图栏）。

意外恢复路径（都已内建）：
- 投屏/共享中误按 Esc 退出全屏 → 放映**不中断**（自动降为窗口放映，观众画面仍干净），
  演讲者视图弹横幅提示，受管双屏可点“恢复全屏”；
- 窗口放映中误按 Esc → 退出放映（观众会短暂看到浏览态），演讲者视图弹“放映已结束”
  横幅，点“重新放映”**免手势瞬时恢复**窗口放映；
- 误关演讲者窗口 → 放映不中断（降为单窗放映），重按 `P` 静默重开并自动同步；
- 放映窗口被误关/误刷新 → 演讲者视图弹“重新打开放映窗口”，页码经 URL hash 自动恢复；
  刷新后 2 秒内心跳自动把主窗拉回窗口放映（讲者窗被会议软件长时间遮挡时浏览器可能
  节流心跳，切回讲者窗即立即补发）；
- 需要“讲者窗开着、主窗留浏览态翻缩略图”的排练形态：进入放映后按一次 Esc 即可
  （明确退出后心跳不会把主窗拉回放映）。

**建议：正式汇报前在排练时先点一次“演讲者放映”完成授权**，正式开播即零弹窗直达。

### 降级链（自动，无需记忆）

| 场景 | 行为 |
|---|---|
| 单屏 / 镜像模式 | 弹选择卡：“演讲者视图＋窗口放映”（主推，远程会议/看讲稿）或“直接全屏放映”（镜像投屏） |
| Safari / Firefox（无 Window Management API） | 打开演讲者视图 + 主窗自动进窗口放映；现场投屏拖窗后按 `F` 全屏 |
| “窗口管理”授权被拒 | 同上手动流程；重新授权：地址栏左侧 ⓘ → 网站设置 → 窗口管理 → 允许，刷新 |
| 放映中拔掉外接屏 | 自动退出全屏、降为窗口放映（放映不中断）并提示 |

## 逐字稿机制

`#speaker-notes` = JSON 字符串数组，项数 == 页数，`\n\n` 分段。演讲者视图读它。每页也可用
`data-speaker-notes="…"` 属性覆盖单页（属性优先于数组）。

## 导出 PDF

两条路径，按用途选：

**快捷路径（现场应急）**：浏览器 `⌘P`（或帮助浮层里的“导出 PDF”按钮）→
目标“另存为 PDF” → 每页一片、尺寸 1920×1080、无页边距（`@page` 已由播放器注入）。
缩略图栏、控制条、演讲者 UI 均不入印。

**交付路径（推荐）**：`scripts/export-pdf.mjs` 一次产出两种交付物，自带硬闸校验：

```bash
node scripts/export-pdf.mjs <deck.html>            # 两种都导，落 deck 同目录
  --slides           # 只导纯幻灯片 PDF（297mm×167.0625mm 全幅 16:9 矢量，无黑边）
  --handout          # 只导二合一 handout（A4 横版：上幻灯片 + 下逐字稿）
  --rp <id>          # 按 <section data-rp="id"> 过滤分报告子集（文件名自动带 -id 后缀）
  --out <dir>        # 输出目录
  --author <name>    # PDF Author 元数据（默认作者署名，以公司/项目组名义交付时覆写）
  --date <YYYYMMDD>  # 文件名日期（默认当天）
  --keep-temp        # 保留中间静态 HTML（排障）
```

产物命名 `<deck 基名>[-rp]-幻灯片[和逐字稿]-<日期>.pdf`，自动写入 PDF 元数据
（Title/Author/Creator）。判读：脚本 exit 0 即全部通过——页数=页码、页面尺寸
在容差内、逐字稿零溢出（自适应梯子：缩字号→dense→双栏；仍溢出则报错列页码，
去精简逐字稿或拆页）。handout 前置硬闸：`#speaker-notes` 条数必须等于页数。
`data-deck-skip` 页不入印（与浏览器打印行为一致）。

## 无头核验（交付前）

```bash
cd scripts && npm i && npx playwright install chromium   # 首次
node verify-presenter.mjs <deck 绝对路径>   # 放映增强层无头断言（控制条/协议/窗口放映/降级链），须全绿
node verify-mobile.mjs <deck 绝对路径>      # 手机端形态无头断言（阅读态/滑动/进度/总览），须全绿
node measure-geometry.mjs <deck 绝对路径>   # 每页 footGap/headGap；负数 = 内容与页眉/页脚重叠
node capture-deck.mjs <deck 绝对路径> audit # 逐页 PNG 落 scripts/_audit/ + so/bo 溢出报告
node export-pdf.mjs <deck 绝对路径>         # PDF 导出（自校验页数/尺寸/逐字稿溢出，exit 0 即过）
```

判读：`footGap/headGap > 15` 为过线；`so>2` 真裁切、`bo>2` 容器密集。
**so=0 且 bo=0 不代表安全**——居中 body 的表格对称溢出探测不到，以几何量测为准。
截图逐张肉眼过一遍：字重、间距、对齐、留白，几何全过 ≠ 好看。
双屏放映路径（授权、交换屏幕）无头测不了，须按 authoring-checklist P3 真双屏过一遍。
手机端同理：设备模拟能量几何，量不出真机的滚动惯性与地址栏收起，交付前真机各开一次。

**整文件覆盖升级 `deck-stage.js` 之后，两个核验脚本都要重跑。** `verify-presenter.mjs`
依赖它的 open shadowRoot 与 `.overlay` 类名；`verify-mobile.mjs` 依赖它的 `dock-top`
属性、`deckfit` 事件与 `fitBox` 属性，缺任何一个都会静默退化成竖屏满屏黑边。

## 排障附录：多屏 API 在 file:// 下的边界（2026-07-09 实测存档）

供后续维护者复用的调研结论（📘 官方 + 🔬 实测），避免重复踩坑：

- **file:// 属 secure context**：`isSecureContext=true`，`getScreenDetails` /
  `requestFullscreen({screen})` / `window-management` 权限（状态 `prompt`）均可用，
  **无需本地服务器**。（🔬 headless Chromium 实测）
- **`window.screen.isExtended` 免授权**，镜像桌面 = false（镜像是单逻辑屏）——
  所以“镜像投屏用 F、扩展桌面用 P”是可自动判别的。
- **一键双屏 = Fullscreen Companion Window**（Chrome 104+ 默认开启）：同一次点击
  手势内先 `requestFullscreen({screen: 观众屏})` 再 `window.open(演讲者屏坐标)`，
  顺序不能反。（📘 developer.chrome.com/docs/capabilities/web-apis/window-management、
  w3c/window-management HOWTO.md）
- **Capability Delegation 在 file:// 下不可用**：`postMessage(msg, {delegate:'fullscreen'})`
  要求具体 targetOrigin，而 file:// 的 origin 是 opaque 的 `"null"`——
  `targetOrigin:'*'` 抛 NotAllowedError，`'null'` 抛 SyntaxError，两头堵死。
  （📘 wicg.github.io/capability-delegation/spec.html）
  故“交换屏幕”不走 delegation：主窗收到请求后直接 `requestFullscreen({screen: 另一屏})`
  （Plan A）；若被手势策略拒绝，自动在放映屏出“点击此处完成屏幕交换”确认层（Plan B）。
  验证命令（演讲者窗 console）：
  `window.opener.postMessage({t:1},{targetOrigin:'*',delegate:'fullscreen'})` → 预期 NotAllowedError。
  若未来改为 http(s) 分发，可改用 delegation 免掉 Plan B。
  **v3 补充**：窗口放映不涉及全屏 API（上游 `__omelette_presenting` 消息即生效、无需
  用户手势），“重新放映”在非受管场景可免手势瞬时恢复——这正是绕开 file:// 下
  delegation 限制的原理，远程会议场景因此没有点击层。
- **授权弹窗可能耗尽点击手势**：`getScreenDetails()` 弹授权框后
  `navigator.userActivation.isActive` 可能已为 false，此时代码提示“再点一次”
  （授权已记住，第二次点击零弹窗直达）。这就是“排练时先点一次”交付口径的由来。
